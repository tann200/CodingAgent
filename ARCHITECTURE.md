# Architecture

## System Boundary

CodingAgent is a local coding-agent application. Its public entry point is the `codingagent` console script, which resolves to `src.main:main`. It can run a Textual UI, execute a single headless task, or expose an optional local HTTP service. The intended unit of work is a task scoped to a caller-selected repository directory.

The process is not a security-isolated multi-tenant platform. Model providers, MCP servers, shell commands, project hooks, local session stores, and the optional HTTP server all run in the local user's environment.

## Runtime Flow

```text
CLI or Textual UI
        |
        v
src.main -> Orchestrator.run_agent_once() (single async graph invocation)
        |
        v
Unified 6-Node Graph Topology (2026 Canonical Architecture)
        |
        +--> initialize (deterministic ModelRuntimePolicy & capability resolution)
        |       |
        |       v
        +--> agent_loop <--------------------+--------------------+--------------------+
        |       | (outcome)                  | (approved)         | (deferred-rollback | (TurnGroup-atomic
        |       +--> approval ---------------+                    |  surgical retry)   |  compaction)
        |       +--> verify --------------------------------------+                    |
        |       |       | (passed or recovery budget exhausted)                        |
        |       +-------+--> finalize (Transaction Settlement Guard) -> END            |
        |       +--> compact ----------------------------------------------------------+
        |
        v
Orchestrator.execute_tool() (parallel read-only waves, serialized mutations)
        |
        v
Tool execution pipeline
        |
        v
Tool registry -> src/tools implementation
```

The live orchestration pipeline executes a single self-contained invocation of the unified 6-node graph topology (`initialize -> agent_loop -> [approval | verify | compact | finalize] -> END`) compiled by `src/core/orchestration/graph/builder.py:compile_canonical_graph()`. All 2026 model tiers share this identical topology while `ModelRuntimePolicy` (`src/core/orchestration/graph/runtime_policy.py`) scales immutable budgets, flat single-purpose primitive toolsets (`compact-flat` 14 tools for `<8.5B` `nano` and `9-14B` `compact`, `standard-flat` 20 tools for `15-70B` dense & MoE `standard`, `frontier-flat` 26 tools for `frontier`), read-only wave parallelism, and targeted vs. full verification. All legacy cognitive nodes and obsolete topology compilers have been retired.

## Components

### Entry Points And UI

- `src/main.py` parses CLI flags (`--output text|json|stream-json`, `--private` ephemeral mode, `--parallel` timestamped git worktree isolation via `src/cli/headless_stream.py`), initializes runtime settings, and selects headless or Textual execution.
- `tui/tui_src/ui/` implements the Textual 8.1.0 client (`AgentBridge` is the strict boundary between UI state and `src.core` orchestration/providers — `app.py` holds zero `src.core` imports or dynamic `spec_from_file_location` loaders), featuring native `Markdown.get_stream()` live streaming (`StreamView`) with in-place finalization and smart auto-scroll anchoring (`↓ Jump to latest`), semantic CSS theme variables across all built-in dark/light themes (`/theme`), responsive `< 110`-column sidebar auto-hiding (`Ctrl+B`), auto-growing input (`ChatTextArea`), native `Collapsible` `ThinkingProcess` and `BashBlock` widgets, native `textual.command.Provider` (`palette_provider.py:CodingAgentCommands` under `Ctrl+P`/`Ctrl+O`), terminal control-sequence sanitization (`terminal_sanitize.py`), bounded async chat-log pruning, sequential message-queue draining, cross-model history normalization (`history_normalizer.py`) on `/provider` and `/model` switches, and strict `Path.is_relative_to` + secret/git-internal blocking on `@file` expansions. `_app_slash_commands_mixin.py` provides interactive slash commands (`/status`, `/doctor`, `/skills`, `/theme`, `/advisor`, `/btw`, `/queue`, `/reasoning`, `/compact`, `/fast`, `/provider`, `/model`).
- `src/cli/` implements the headless `session`, `status`, `doctor`, `local-launch`, `context-report`, `skill`, `mcp`, and `diff` subcommands, plus `headless_stream.py` (sanitized NDJSON `StreamJsonEmitter` and `ParallelWorktreeSession`).

### Orchestration

- `src/core/orchestration/orchestrator.py` owns the agent instance and exposes `run_agent_once()` and `execute_tool()`.
- `src/core/orchestration/inference_loop.py` builds the run state, resolves provider/model capabilities, embeds immutable runtime policy, invokes the native async `AgentRunner` (`src/core/orchestration/runner.py`) once per task, applies turn limits and cancellation handling, and returns the result.
- `src/core/orchestration/runner.py` executes the canonical 6-stage state machine (`initialize -> agent_loop -> [approval | verify | compact | finalize] -> END`) directly in Python without LangGraph `StateGraph` compilation or channel serialization warnings, enforcing strict `NodeOutputSchema` validation, `merge_or_replace_list` linear history reduction, `recursion_limit`, and redacted crash-recovery snapshots persisted to `SessionStore` / `checkpoint_saver`.
- `src/core/orchestration/graph/` contains slimmed state definitions (`AgentState`), canonical pipeline builder (`builder.py`), deterministic routing (`canonical_routing.py`), checkpointing, and the 6 cognitive stage nodes (with legacy `wait_for_user_node.py`, `memory_update_node.py`, and `dag_parser.py` retired).
- `src/core/orchestration/graph/runtime_policy.py` and `policy.py` define the authoritative target state schema (`runtime`, `run`, `pending_action`, `last_action`, `verification`) and 4-profile `ModelRuntimePolicy` (`nano`, `compact`, `standard`, `frontier`).
- `initialize_node.py` resolves runtime metadata, `ModelRuntimePolicy`, and flat toolset configuration deterministically without LLM calls.
- `frontier_loop_node.py` (aliased as `agent_loop_node`), `frontier_dispatch.py`, and `loop_guards.py` execute iterative native-tool loops with structured `assistant.tool_calls` + `role="tool"` history, signed `thinking_blocks` / `reasoning_content` preservation, KV-cache prefix stability, parallel read-only tool waves, `bash` file-mutation detection, `ReadDedupCache` (6-entry pure-read cache invalidated on any mutation or `bash`, compacting large unchanged `read_file` repeats to a one-line notice), closest-match hallucinated tool hints, Turn-1 stat-only `<workspace_bootstrap>` (`workspace_bootstrap.py`), compact `ACTIVE PLAN` anchors, adaptive verification-retry temperature deltas `(-0.15, +0.15, 0.0)`, truncated-output (`finish_reason == "length"`) chunking recovery feedback, duplicate failing-call short-circuiting, and in-loop recovery guidance.
- `approval_node.py` validates action digest integrity, suspends non-blockingly for user/plan approval, and resumes the approved `next_action` cleanly.
- `verification_node.py`, `verification_helpers.py`, and `validation_authority.py` enforce SHA-256-deduplicated targeted or full polyglot verification (Python with shallow import-aware targeted pytest fallback, JS/TS `package.json`, Rust `Cargo.toml`, Go `go.mod`, and sandboxed allowlisted `.codingagent/verify.yaml`) with **Deferred Rollback** (`agent_loop -> verify -> agent_loop` recovery loop), POSIX `set -o pipefail` wrapping on piped bash commands, quote-aware demotion of failure-masking operators (`;`, `||`, `&`) to `unconfirmed`, and opportunistic **red→green validation debt** tracking enforced by `completion_contract.py`.
- `compact_node.py` performs 2-stage `TurnGroup`-atomic deterministic compaction (provenance-preserving tool-output stubbing followed by `<context_checkpoint>` turn-group folding) that never splits `assistant.tool_calls` from matching `role="tool"` messages.
- `finalize_node.py` enforces a fail-closed **Transaction Settlement Guard** (committing open snapshots only when verified or rolling back any unverified/failed/cancelled deferred-rollback edits), persists trajectories deterministically, and terminates to `END`.

Graph checkpoints can persist and rehydrate graph state. They improve crash recovery, but do not make arbitrary tool side effects transactional.

### Tool Execution And Safety

`src/core/orchestration/tool_execution_pipeline.py` is the normal enforcement point for model-initiated tool calls, coordinating four single-responsibility stages under `src/core/orchestration/pipeline/` (`preflight.py`, `permissions.py`, `dispatch.py`, `post_hooks.py`). It performs canonicalization, read-before-write and scope checks, permission checks, approval handling, contract validation, rollback snapshots where supported, hooks, timeout handling, event publication, and tracing. Oversized string tool outputs (above tier-adaptive ceilings: `nano` 6,000, `compact` 12,000, `standard` 24,000, `frontier` 48,000 chars) are reduced deterministically by content type (`validation`, `git`, `diff`, `search`, `json`, `generic`) in `src/core/orchestration/tool_output_reducer.py`, while the pre-redacted raw output is stored in a per-session bounded LRU `ToolOutputStore` (32 entries / 4 MiB max) retrievable on demand via the read-only `read_tool_output(handle, offset, limit)` tool.

`src/tools/` provides the registered functions managed by a single authoritative `ToolRegistry` (`src/tools/_registry.py`; `src/core/orchestration/tool_registry.py` and `registry_builder.py` re-export and delegate directly). Important groups are:

- `_file_io.py`, `_edit_tools.py`, `patch_tools.py`, and `repo_write_tools.py` for workspace modification. `read_file` supports 1-based inclusive `start_line`/`end_line` slicing and applies a **Context-Aware Read Guard** for un-sliced reads of large files (> 40% of remaining context or > 500 lines on `compact`/`nano` tiers), returning a 30-line preview without satisfying read-before-write for blind full-file overwrite (while permitting surgical `edit_file_atomic` edits strictly on lines shown in the preview). Model-facing file edits standardize on three canonical primitives (`write_file`, `edit_file_atomic`, `apply_patch`), while legacy edit aliases (`edit_file`, `edit_by_line_range`, `multiedit`, `edit_code_block`) remain registered and executable with `schema_visibility="alias_only"`.
- `_bash_exec.py`, `bash_security.py`, and `sandbox.py` for command execution. `bash_security.analyze_bash_command()` + quote-aware `split_shell_segments()` is the single authoritative command analyzer across both `tool_preflight.py` and `_bash_exec.py`. Sandboxed execution isolates `/tmp` using `--tmpfs` (avoiding host temp data exposure), prepends the active Python runtime bin directory to sandbox `PATH` (and resolves bare `python` to `sys.executable` when absent from `PATH`, returning exit `127` instead of a profile-failure crash on `sandbox-exec` `execvp()` ENOENT), and fails closed by default if no backend is available or enforcing, unless explicitly opted out via `CODINGAGENT_SANDBOX_ALLOW_UNENFORCED=1` or `CODINGAGENT_SANDBOX_LEVEL=off`. When an enforcing OS sandbox is active, `bash()` permits quoted metacharacters and safe read/test pipelines (`|`, `&&`, `||`, `;`) where every parsed segment passes full AST, tier, flag, secret-path, and network checks; unconfined fallback and `bash_readonly()` retain strict operator blocking as a fail-safe.
- `repo_read_tools.py` (including `read_tool_output`), `lsp_tools.py`, and `project_tools.py` for repository inspection.
- `verification_tools.py` (including consolidated auto-formatting via `format_file` and `run_formatter`) and `lint_dispatch.py` for validation.
- `memory_tools.py`, `todo_tools.py`, `plan_mode_tools.py`, `advisor_tool.py` (opt-in `ask_advisor` dormant by default, capped at `max_uses=3`/session, with secret redaction and optional human handoff), and `subagent_tools.py` (`<= 400 LOC`, opt-in `delegate_task(mode="scout"|"worktree")` with read-only lethal-trifecta isolation for `scout`, temporary git worktrees for `worktree`, and fail-closed exclusion from `compact-flat`) for agent state and workflow support; `src/core/orchestration/btw_query.py` executes parallel read-only `/btw` side queries without mutating main conversation history.
- `src/config/toolsets/` defines strictly the 3 canonical model-facing flat single-purpose primitive toolsets (`compact-flat.yaml` 14 tools without `delegate_task`, `standard-flat.yaml` 20 tools, `frontier-flat.yaml` 26 tools — all including `read_tool_output` and `load_skill`) intersected fail-closed with role and `explore_mode` permissions. Legacy role toolsets (`analysis`, `coding`, `debug`, `planning`, `review`), `capability_tools.py`, and `formatter.py` have been retired.

`ToolRegistry.call()` routes invocations through guarded orchestrator execution (`Orchestrator.execute_tool()`), ensuring read-before-write validation, workspace confinement, secret redaction, and transactional pre-call snapshots for all mutations (including unlinking newly created files/directories on rollback). Tool discovery fails closed if non-optional built-in modules fail to import, and toolset resolution fails closed if any configured tool is absent.

### Context, Memory, And Repository Intelligence

- `src/core/context/` constructs prompts from a minimal 1-line identity anchor (`SOUL.md`), unified tier-aware role contracts (`operational*.md`, `scout.md` routing post-edit verification through the `verify` graph node), active-tool-gated `<tool_guidance>` and canary-tested `<security>` blocks (`tool_prompt_sections.py`), thin model-family delta partials (`src/core/prompts/templates/`), progressive-disclosure skill catalogs (`agent_brain_loading.py:discover_skills()`, `render_skill_catalog()`, collapsing bundled skills onto one line on `nano`/`compact` tiers while keeping workspace/user skills full), ancestor `AGENTS.md`/`CLAUDE.md` + root `ARCHITECTURE.md` (3,000-char cap) + lazy SHA-256-deduplicated nested subtree `AGENTS.md`/`CLAUDE.md` (`instruction_files.py`), optional prior-session context, LSP context, and retrieved snippets.
- `src/core/memory/` uses a single canonical SQLite `SessionStore` (WAL + FTS5) — or ephemeral in-memory `NullSessionStore` when `--private` / `CODINGAGENT_PRIVATE=1` is active (zero `.codingAgent/` session, trace, snapshot, or timing disk writes) — with portable secret-redacted JSONL import/export (`jsonl_io.py`), an on-demand `TurnGroup`-atomic `CompactionEngine` (invoked only when context thresholds are crossed or on explicit `/compact`), deterministic first-turn session titles (LLM titles opt-in via `CODINGAGENT_LLM_SESSION_TITLES=1`), and sidecar diagnostics. File-level transactional snapshots and rollback (including lossless binary files) are unified in `RollbackManager`; `JsonlSessionStore`, `GitSnapshotManager`, and `advanced_features.py` have been retired.
- `src/core/indexing/` extracts symbols via `SymbolGraph` (with PageRank importance and call-graph context), maintains a repository index, wires live `LSPClient` `didChange` diagnostics into `ContextBuilder`, and keeps `VectorStore` semantic embeddings strictly opt-in (`CODINGAGENT_ENABLE_VECTOR_STORE=1` or project `vector_store.enabled: true`) so short tasks incur zero embedding/stub overhead.
- `src/config/agent-brain/roles/` (`operational*.md` and `scout.md`) and `src/config/agent-brain/skills/` (focused YAML-frontmatter playbooks replacing legacy multi-role personas: `code_review`, `debug_checklist`, `explore_codebase`, `refactor`, `security_review`, `write_tests`, etc.) supply prompt-time single-agent and bundled skill content, merged behind workspace (`.codingagent/skills/`, `.agents/skills/`, `.claude/skills/` — `safe_resolve`-confined and wrapped in nonce-fenced `<project_skill>` envelopes) and user (`~/.codingagent/skills/`) skill scopes. Delegated subagents also receive a `<subagent_budget>` capsule (`subagent_payloads.py`) specifying step limits, partial-deliverable gap reporting, and mandatory tool grounding in `scout` mode. Reusable agent skills packaged for external agent runners (Agensi, Claude Code, Cursor) reside in `src/config/skills/<skill>/SKILL.md`.

### Providers And Evaluation

- `src/core/inference/` manages provider discovery, capability profiles, pure-stdlib DoS-bounded GGUF v2/v3 header & tensor-table inspection (`gguf_header.py`, opening via `O_NOFOLLOW` + `stat.S_ISREG` with strict 16 MiB / KV / string / array / tensor ceilings, hybrid Gated DeltaNet KV-layer counting, and exact memory/KV-quant context fitting wired into `local_runtime_autotune.py`, `kv_cache_governor.py`, and `codingagent local-launch`), zero-config local runtime auto-tuning (`local_runtime_autotune.py`), `KVCacheGovernor` calibration (including Apple Silicon headroom, `num_ctx`, `kv_cache_quant`, and MoE KV scaling), routing, token counting, streaming, retries, fallback, telemetry, and adapters (`AnthropicAdapter`, `GeminiAdapter`, `GroqAdapter`, `OllamaAdapter`, `OpenAICompatAdapter`, `MlxAdapter`, `LlamaServerAdapter`). `GroqAdapter` and `GeminiAdapter` enforce strict OpenAI-compatible payload hygiene (omitting legacy `functions` mirroring and Ollama's non-standard `think` field) and expose `supports_native_tools = True`. `LlamaServerAdapter` pins `id_slot: 0` (overridable via `CODINGAGENT_LLAMA_SLOT`, omitted for parallel workers) alongside `cache_prompt: true` and uses a patient local timeout (`CODINGAGENT_LOCAL_TIMEOUT`, default `600s`, shared with `OllamaAdapter`). `thinking_utils.py` provides portable `ReasoningEffort` (`off|low|medium|high|unset`) mapped defensively per provider with dynamic `compact`-tier thinking-budget clamping that bumps automatically on `verification_node` recovery retries, and `tool_parser.py:parse_response_tool_call()` rescues tool calls emitted inside `reasoning_content` when `content` is empty. `OllamaAdapter` normalizes bare root URLs (`http://host:11434` → `/api`) and emits standard `usage` dicts (`prompt_tokens`/`completion_tokens`) for cost tracking and evaluation telemetry. Anthropic and OpenAI/local adapters support prompt-cache prefix stability via `system_prompt_dynamic_boundary`.
- `src/config/providers.json` contains read-only bundled provider defaults (including inactive presets for `groq`, `gemini`, `mlx`, and `llama_server`). Runtime active provider, active model, credentials, endpoint overrides, and optional per-provider/per-model `policy_tier` / `model_policy_tiers` overrides are stored exclusively in user-scoped `UserPrefs` (`~/.coding_agent/prefs.json`, `0o600`) and layered over bundled defaults at load time. When native tool calling is active, `static_prompt_parts.py` omits the duplicate `<available_tools>` text block from the system prompt and omits pre-call narration (`<thinking_mode>`) across all tiers, while `nano`/`compact` runtime policies emit tightened lossless OpenAI tool schemas via `ToolRegistry.get_openai_functions(compact=True)`.
- `src/core/evaluation/` includes 23 executable-verified scenarios (running inside isolated temporary workspaces with scoped sandboxed `run_tests`/`bash`/`delegate_task` approval, optional per-turn `[EVAL]` debug tracing via `ScenarioEvaluator(debug=True)` or `CODINGAGENT_EVAL_DEBUG=1`, and typed-event token accounting), regression comparisons (failing on dropped baseline scenarios), benchmark-driven diff gating (`codingagent bench-diff` with exit codes `0` improved / `1` regressed / `2` noise / `3` error), comparison utilities, and SWE-bench grading harnesses. `src/cli/context_report_cmd.py` (`codingagent context-report`) computes offline static prompt, instruction-file, skill-catalog, and tool-schema token budgets per tier. Completion contracts (`completion_contract.py`) also check explicitly requested named deliverables on mutating tasks to prevent premature multi-file exits, while `ValidationDebtTracker` (`validation_authority.py`) tracks genuine baseline test/lint failures (ignoring non-failure exit codes `5`/`126`/`127` and skipped runs) and `run_tests` falls back to `[sys.executable, "-m", "pytest"]` when `pytest` is absent from `PATH`. CI runs deterministic, acceptance, and mock-backed coverage by default; live-provider checks are scheduled or manually enabled.

### Events, Observability, And Server

- `src/core/messaging/` is the typed asynchronous event layer used by the UI bridge and server delivery (`BashApprovalRequired`, `SpawnPermissionRequired`, `ToolExecute*`).
- `src/core/telemetry/`, `src/core/observability/`, and `src/core/logger.py` collect traces (`OtelExporter` and `tracer.py` sharing a single `TracerProvider` and redacting secrets), metrics, and logs. OpenTelemetry support is optional.
- `src/server/` contains an optional FastAPI application for task submission, SSE, WebSockets, scheduler endpoints, and metrics. It is started only when `CODINGAGENT_HTTP_SERVER=true`, defaults to loopback, enforces startup exposure validation, WebSocket Origin validation, and constant-time metrics auth.

## State And Data

Project-local runtime configuration is read from `.codingAgent/`. User-level preferences, provider credentials, session history, checkpoints, indexes, summaries, metrics, and audit/trace records are managed by their respective core services. Never assume session data is safe to expose to an LLM or remote client without redaction.

Project-local configuration merges `.codingAgent/config.json` / `.codingAgent/config.local.json` and `.codingAgent/settings.json` / `.codingAgent/settings.local.json` (in that order). `codingagent init`, `codingagent mcp add`, and active configuration resolution all use `.codingAgent/`; the legacy `.agent` and `.localAgent` names are not used. Diagnostic step timings in `.codingAgent/timings.json` are capped to a bounded ring buffer (default `200` recent entries). Outbound MCP servers started synchronously via `Orchestrator.run_deferred_init_sync()` run on a dedicated persistent daemon event loop owned by `McpServerManager` and torn down cleanly in `Orchestrator.close()`.

## Trust Boundaries

- Provider output is untrusted and must remain subject to tool permissions and validation.
- Repository content, tool output, web content, prior-session memory, MCP responses, and hook output can contain prompt injection. Untrusted web pages (`web_tools.py`), MCP tool outputs (`mcp/manager.py`), project instruction files (`instruction_files.py`), and compaction summaries (`compact_node.py`) are wrapped in per-process random nonce envelopes (`src/core/security/untrusted_envelopes.py`) that escape case/whitespace/newline forged closing tags.
- Shell commands and project hooks are host-code execution. Sandbox availability is enforced fail-closed by default; commands are denied if no enforcing backend is present unless explicit unconfined opt-out is granted. Enforcing OS sandboxes mask host credential directories (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.docker`, `$XDG_CONFIG_HOME/{gh,gcloud,op,sops/age}`) via SBPL last-match-wins `(deny file-read*)` or `bwrap --tmpfs`, overridable explicitly via `--sandbox-expose`. `PreToolUse` hooks execute strictly after `PermissionPolicy` (never escalating a `deny`/`ask` verdict) and project `.codingAgent/hooks*` files require SHA-256 digest approval in live pipeline runs.
- Mutating file, patch, AST, LSP, and `git_restore` tools share a single pre-write guardrail (`src/tools/_file_io.py:_pre_write_check`) plus lexical+realpath `check_file_safety()` (`_workspace_guard.py`) enforcing secret-file protection (with `.env.example`/`.sample`/`.template` and `*.pub` allowlisted), `.git` internals protection, dangling-symlink write refusal, multi-hardlink (`st_nlink > 1`) protection, workspace confinement, `WorkspaceGuard`, project `deny_write` patterns, read-before-write, and binary checks before writes. Read-only/untrusted-ingestion roles enforce fail-closed lethal-trifecta isolation (`assert_lethal_trifecta_isolated`) against mutating tools. Outbound remote MCP clients (`http`, `sse`, `ws`) validate URLs against SSRF/obfuscated-loopback targets via `src/tools/web_tools.py:validate_mcp_url` and reject unvalidated HTTP redirects.
- The optional server is a local control plane, not a general public API; task workdirs enforce an approved root allowlist (`CODINGAGENT_ALLOWED_WORKSPACE_ROOTS`, defaulting to the server's working directory), queue admission is bounded, and cancelled queued tasks abort before orchestrator construction.

## Design Constraints

- Keep new tools declarative and registered through the existing registry.
- Preserve the central tool execution path for all model-controlled actions.
- Enforce read-before-write, workspace boundaries, explicit permission metadata, and verifiable postconditions for mutations.
- Treat logs, traces, sessions, exports, and HTTP responses as potential secret-exposure paths.
- Add tests at the graph and tool-pipeline boundary whenever changing safety, routing, or completion semantics.
