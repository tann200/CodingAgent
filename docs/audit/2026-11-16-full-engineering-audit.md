## 1. Executive Summary

CodingAgent has assembled an ambitious architecture: a unified 6-node canonical LangGraph (`initialize -> agent_loop -> [approval | verify | compact | finalize] -> END`), strict node-output schema enforcement, a tiered flat-toolset capability design, bubblewrap/SBPL sandboxing, multi-hop SSRF guards, secret redaction, SQLite FTS5/JSONL dual session stores, AST bash analysis, and a decoupled Textual TUI bridge.

However, deep file-by-file auditing reveals **six systemic failure clusters** that break determinism, safety, or core execution:

1. **Live TUI Message Dispatch Is Broken in Textual 8.1.0 (`CRITICAL`)**: Because `AgentApp`'s 5 mixins inherit from `AgentAppProtocol` (metaclass `type`) rather than Textual's `_MessagePumpMeta`, **zero `@on(...)` handlers** on the mixins—and `handle_slash_command`—are registered in `AgentApp._decorated_handlers`. Verified live: `app._get_dispatch_methods(...)` returns `[]` for `StreamChunkEvent`, `SlashCommand`, and `ChatTextArea.Submitted`. Additionally, `--workdir`, `--trusted`, and `--plugin-dir` CLI flags are assigned *after* `AgentApp()` already constructed `AgentBridge` and `Orchestrator`.
2. **Core LangGraph Execution Loops & State Corruption (`CRITICAL`)**: `frontier_loop_node` and `verification_node` return full `list` histories into `AgentState.history` whose `merge_or_replace_list` reducer concatenates rather than replaces—causing $O(2^k)$ exponential history duplication; tool-budget exhaustion or LLM errors loop back into `agent_loop -> agent_loop` until `GraphRecursionError`; `delete_file` verification omits `verification_passed=True` so `finalize_node` rolls back successful deletions; `RollbackManager.commit_step()` never cleans up snapshots because `_step_to_snapshot` is never populated; and `_verified_file_hashes` is absent from `AgentState`.
3. **Broken Core Tools & Split-Brain Registry (`CRITICAL`)**: `list_dir`/`list_files` never appends inside its loop (verified live: `list_dir(".")` always returns `items: []`); `GrepContract` and `GeneratePatchContract` fail against actual tool inputs/outputs inside `Orchestrator.execute_tool()`; `example_registry()` strips `__tool_meta__`, `schema_visibility`, and `get_permission_kind()`; and 15+ Track 1 dispatchers in `capability_tools.py` have broken kwargs/imports.
4. **Trust Boundary & Sandbox Bypasses (`CRITICAL` / `HIGH`)**: Untrusted workspace `.codingAgent/settings.json` escalates `PermissionLevel` before trust checks; `ToolHookRunner` runs workspace `.codingAgent/hooks/` shell scripts even under `--untrusted`; `McpServerManager` checks workspace trust only for `stdio` (leaving `http`/`sse`/`ws` SSRF/tool-poisoning open); `env python3 -c` and `xargs python3 -Bc` bypass `bash`/`bash_readonly` gates; `run_sandboxed()` fails to call `_run_subprocess_proc_group()`, breaking timeout kills; and `lint_dispatch.py`/`verification_tools.py` fall back to raw `subprocess.run()` on sandbox `RuntimeError`.
5. **Inference, Context, Memory & Server Defects (`CRITICAL` / `HIGH`)**: `CircuitBreaker.is_open()` mutates `_probe_in_flight = True` on read, wedging recovery; streaming HTTP 4xx/5xx errors return `ok=True, text=""`; `auto_compactor.compact_messages()` orphans `role="tool"` messages; `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` excludes tool/skill definitions from Anthropic prompt caching; `JsonlCheckpointSaver` uses unsafe `pickle` on repo files; and HTTP `POST /task` leaks per-request `Orchestrator` `atexit` closures while dropping prior session history in `Orchestrator.msg_mgr`.
6. **Evaluation & Test-Gate Blind Spots (`HIGH`)**: `tests/conftest.py` globally sets `CODINGAGENT_SANDBOX_ALLOW_UNENFORCED=1`; `ScenarioEvaluator` uses brittle substring checks for 14/23 default scenarios; `swebench.py` pollutes extracted patches with `.codingAgent/` runtime files and mis-parses JSON-encoded `FAIL_TO_PASS` lists; and `tests/unit/test_tui_*` called mixin methods directly instead of posting Textual messages, hiding the broken `@on` mixin dispatch.

## 2. Architecture Strengths

1. **Unified 6-Node Graph & Strict Node Schemas (`src/core/orchestration/graph/builder.py`, `canonical_routing.py`, `state_schemas.py`)**: Replaces fragmented per-tier graphs with a clean deterministic state machine (`initialize -> agent_loop -> [approval | verify | compact | finalize] -> END`), backed by `CODINGAGENT_STATE_SCHEMAS_STRICT=1` validation on every node output.
2. **Fail-Closed Autonomous Mode & Toolset Integrity (`src/tools/tools_config.py`, `src/config/toolsets/loader.py`)**: `--autonomous` fails closed unless `--autonomous-approve` allowlists actions; `resolve_toolset(..., fail_closed=True)` and `validate_all_toolsets()` catch missing/unregistered tools cleanly.
3. **Strong Security Primitives (`src/core/security/redaction.py`, `src/tools/_path_utils.py`, `src/tools/web_tools.py`)**: Multi-pattern token/PEM/URI redaction with bounded regexes, strict `safe_resolve()` symlink validation, atomic `mkstemp` + `os.replace` writers (`_file_io.py`, `_edit_tools.py`), and multi-hop redirect SSRF validation with peer-IP checks.
4. **Tier-Adaptive Runtime Policy & Parallel Read Waves (`runtime_policy.py`, `frontier_dispatch.py`, `tool_result_safety.py`)**: Clean separation of tool output truncation budgets (6K–48K), pure-read wave batching with serial mutation barriers, and pre-truncation prompt-injection scanning.
5. **Typed Event Architecture & Thread-Safe Bridge Helper (`src/core/messaging/bus.py`, `event_types.py`, `tui/tui_src/ui/core_bridge.py`)**: Well-structured typed event bus and loop-aware `AgentBridge._schedule_callback()` marshaling.
6. **Verification Infrastructure (`verification_node.py`, `verification_helpers.py`, `in_loop_verification.py`)**: Baseline-diffed syntax checking inside `frontier_loop_node`, polyglot JS/TS/Rust/Go/Python verification, and tampered `.codingagent/verify.yaml` rejection.

## 5. Major Missing Capabilities

1. **Working Live-TUI End-to-End Event & Slash/Approval Wiring**: Because `@on` mixin dispatch, `bash.approval_required` mapping, `ModelRouting` (`MessageBus` vs `EventBus`), and doom-loop buttons (`tool.doom_loop_continue`, `agent.interrupt`) are disconnected across TUI and Core, operators lack working interactive provider switching (`/provider`/`/model`), Tier-3 bash approvals, and doom-loop intervention in TUI mode.
2. **Real Multi-Turn History Hydration in HTTP `POST /task` (`src/server/task_endpoints.py:310-337`)**: `task_endpoints.py` loads `prior_messages` from `session_store` and passes them as `messages` to `orch.run_agent_once(...)`, which ignores all messages except `messages[-1]` and reads `history` from `orch.msg_mgr.messages`—making HTTP multi-turn sessions stateless on live `Orchestrator`.
3. **True Persistent, Multi-Worker, Cancellable Scheduler (`src/core/scheduler/worker.py`)**: Job schedules/enabled flags are purely in-memory globals (wiped by restart or `orchestrator_config_reload.py:168`), execute sequentially on a single loop quantized by 60s `heartbeat_interval`, and lack job timeouts/cancellation.
4. **Live LSP Document Synchronization (`didChange` / `didClose`) & Code-Aware Symbol Graph Usage**: `LSPClient` sends `didOpen` once without `didChange` on edits, leaving diagnostics stale after the first edit; `SymbolGraph` call/definition/import edges are not integrated into planning/context assembly.
5. **Executable Ground-Truth Evaluation Suites (`src/core/evaluation/`)**: 14/23 default scenarios rely on brittle substring checks instead of test/AST assertions; no deterministic seed/temperature harness exists; live-provider & real multi-agent delegation harnesses are skipped/disabled in CI.

## 6. Workflow Reliability Issues

1. **`replan_required` Never Cleared (`frontier_completion.py:129-132`, `canonical_routing.py:33-42`) [Critical]**: Once set on an oversized patch, `replan_required` persists in `AgentState` and hijacks subsequent completed/verified passes back into `agent_loop`, eventually skipping `verify` straight to `finalize`.
2. **Cancellation Ignored Inside `frontier_loop_node` & Cancelled Verification Loops Back (`frontier_loop_node.py:528-825`, `verification_node.py:210-342`, `canonical_routing.py:81-105`) [Critical]**: `frontier_loop_node` never checks `cancel_event` across turns/waves; cancelled `verification_node` early-returns without `run["outcome"] = "cancelled"`, so `route_after_verify` re-enters `agent_loop`.
3. **Plan-Mode Gaps & Multi-Tool Batch Corruption (`plan_mode.py:14-20`, `frontier_loop_node.py:578-598`, `approval_node.py:53-108`) [High]**: `PlanMode.BLOCKED_TOOLS` omits `edit_file_atomic`, `multiedit`, `rename_file`, `bash`, `git_commit`; suspending mid-batch drops sibling tools and misaligns `tool_call_id`; `approval_node` allows prior `plan_mode_approved=True` to auto-approve later rejected previews and skips digest verification when empty.
4. **`_sync_msg_mgr_with_final_history` Strips `tool_calls` & Breaks After Compaction (`inference_loop_responses.py:59-136`) [High]**: `<= len` check skips updates after `compact_node` shrinks `history`, and `msg_mgr.append(role, content)` strips `tool_calls`/`tool_call_id`/`name`, corrupting next-turn native tool history.
5. **`MessageManager` Thread Race & Orphan `tool` Messages (`message_manager.py:117-214`, `orchestrator_event_subscriptions.py:134-166`) [High]**: Background distillation mutates `msg_mgr.messages` under `_msg_mgr_lock`, which `MessageManager.append()` never acquires; `_truncate_to_window` orphans consecutive `role="tool"` messages.
